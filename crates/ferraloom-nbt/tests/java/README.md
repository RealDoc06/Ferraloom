The vectors in `vectors.tsv` are generated by `VanillaNbt.java` against the
unobfuscated 26.3 server. They are test inputs and outputs, not decompiled code.
String fields are UTF-8 hex; binary fields are raw hex. Rust tests use the
committed vectors and do not require Java.

Regenerate on devbox (JDK compilation and these small probes are light work):

```sh
repo="$PWD"
cache=/home/doc/code/Ferraloom/.cache/vanilla/26.3
jdk=/home/doc/code/Ferraloom/.cache/toolchains/jdk-25.0.4.1+1/bin
classpath="$cache/versions/26.3/server-26.3.jar:$(find "$cache/libraries" -name '*.jar' -printf '%p:' | sed 's/:$//')"
mkdir -p /tmp/ferraloom-nbt-java
"$jdk/javac" -cp "$classpath" -d /tmp/ferraloom-nbt-java crates/ferraloom-nbt/tests/java/VanillaNbt.java
(cd /tmp && "$jdk/java" -cp "/tmp/ferraloom-nbt-java:$classpath" VanillaNbt) |
  rg '^(parse|error|path|patherror|compare|compressed|account|utf|fallback|numeric|text)\t' > "$repo/crates/ferraloom-nbt/tests/java/vectors.tsv"
```

Passing arguments to the Java class probes individual SNBT strings.
