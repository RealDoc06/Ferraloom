# ferraloom-storage

Vanilla 26.3 (DataVersion 5023) storage. The binary formats come from
`RegionFile`, `RegionFileVersion`, `SerializableChunkData`, `EntityStorage`,
`SectionStorage`, `LevelStorageSource`, `PlayerDataStorage` and `SavedDataStorage`.

Use `IoWorker` for chunk IO. Submission and awaiting are nonblocking; `wait`,
`close` and dropping the worker belong off the tick thread. Its single IO thread
owns the LRU region cache, coalesces pending writes per chunk, serves pending
values to reads, reports write failures and syncs on shutdown.

26.3's directory layout differs from older releases:

- Dimensions: `dimensions/<namespace>/<path>/{region,entities,poi,data}`.
- Players: `players/{data,stats,advancements}/<uuid>.{dat,json}`.
- Saved data: `data/<namespace>/<path>.dat`, in either the world or dimension.

`LevelData` retains the complete level.dat envelope; `SavedData<T>` separates
versioning and dirty tracking from a game system's codec. Chunk, entity and POI
models preserve unknown fields at every modeled compound. `SectionRegistry`
resolves block names/properties and live biome IDs for conversion to the shared
`ferraloom_chunk::LevelChunkSection`. Saving an edited section retains existing
palette entries and their extensions. Opaque block entities and structure starts
are deliberately decoded by later game systems.

Older and newer data versions return an explicit unsupported-version error.
Raw region stream access remains available as a hook for a future DataFixer.
Custom compression ID 127 is recognized and rejected as vanilla does; vanilla
has no custom codec implementation. IDs 1–4 use gzip, zlib, none and Java
LZ4Block streams, including the XXH32 checksum.

## Tests

Run from a committed checkout through `ferraloom-build`:

```sh
ferraloom-build -- cargo test -p ferraloom-storage --locked
ferraloom-build -- cargo test -p ferraloom-storage --locked -- --ignored --nocapture
ferraloom-build -- cargo clippy -p ferraloom-storage --all-targets --locked -- -D warnings
ferraloom-build -- cargo fmt -p ferraloom-storage -- --check
```

The ignored tests need `FERRALOOM_VANILLA_JAR` and JDK 25 (`JAVA_HOME`), which the
builder wrapper supplies. They boot a scratch server on loopback, log in the
fixture player, check the barrel inventory and armor stand, and require a clean
shutdown with no storage errors. Independent Java checks also read all four Rust
compression streams and verify Java/Rust session.lock exclusion.

Fixtures are a seed-12345 flat world generated by vanilla, with three terrain
chunks in two compact region files, entity and POI regions, level.dat, namespaced
saved data, and a real offline player's data, stats and advancement files. Every
NBT/JSON value is compared after Rust reserialization; terrain/entity/POI data is
rewritten using LZ4 before the vanilla boot. The unneeded terrain slots were
removed without altering the retained vanilla chunk streams. No Mojang code or
server binaries are included.

Regenerate the world on devbox with:

```sh
python3 crates/ferraloom-storage/tests/vanilla.py generate \
  --jar /home/doc/code/Ferraloom/.cache/vanilla/26.3/server.jar \
  --java /home/doc/code/Ferraloom/.cache/toolchains/jdk-25.0.4.1+1/bin/java
```

`tests/CompressionVectors.java generate <directory>` emits the deterministic
compression vectors against the shared extracted vanilla jar and libraries.
