# Finite official surface accounting

[behavior-map.json](../compatibility/behavior-map.json) is the authored map.
[surface-coverage.json](../compatibility/surface-coverage.json) is its compact,
deterministic index, generated by the standard-library-only
[surface_coverage.py](../tools/surface_coverage.py). These files inventory work
for the exact official Java 26.3 inputs. Explicit open obligations count as
deliberate accounting. They establish no implementation or paired coverage.

The [existing compatibility contract](compatibility.md#runnable-checks-and-completion-gates)
and [architecture acceptance contract](architecture.md) remain authoritative.
Every required family scenario and the strict family/evidence gates still
apply. Complete inventory accounting cannot replace them or establish a working
replacement. No family status or existing evidence file is changed here.

## Exact finite scope

The committed input pins cover the official outer/inner JARs, six generated
reports and the generated item-report directory. The index accounts for:

- 95 static registries and 7,053 identifiers, including registry-level numeric
  IDs/defaults. Entity, block-entity, item, block and component types have
  separate obligation templates.
- 1,286 block definitions and all 35,723 state IDs, property tuples and defaults.
  State IDs come from the report, including sparse IDs, rather than array indices.
- All 2,475 command nodes under 94 roots, including 1,424 executable nodes,
  1,277 argument nodes, 114 redirect edges and 89 explicit permission objects.
- All 9,883 shipped `data/minecraft/` files across 44 top-level categories.
  Nested `worldgen/*` and `tags/*` kinds remain distinct. Base and embedded
  optional packs retain separate identities, logical IDs and archive paths.
- 155 datapack registry descriptors plus `function` and `structure`, including
  descriptors without shipped instances. Of these registries, 95 are also static.
- All 1,658 generated item reports, exactly matching item-registry membership,
  with 23,072 default component occurrences. 69 of 122 component types have
  default examples; the remaining 53 are explicitly listed.
- All 260 reported packet IDs across five states: configuration 31, handshake 1,
  login 11, play 213 and status 4.
- All 89 OpenRPC methods and 14 named schemas, retaining original method/schema
  content by source pointer and fingerprint, with checked internal `$ref` links.

All non-directory `data/` members of the pinned inner JAR are scanned, across
namespaces. `data/.mcassetsroot` is the sole recorded metadata exclusion.
Unexplained metadata and unclassified resource kinds require review.
The scope deliberately excludes other generated reports such as
`biome_parameters`, client assets, accepted custom-input universes and bytecode
behavior extraction. The fixed inputs do not enumerate every vanilla behavior.

## Reproduce from a clean clone

Use Python 3.10 or newer. No third-party package or project/harness import is
needed by the generator. It never acquires inputs, starts Java, or starts a
server. Missing or changed inputs are errors.

Acquisition/report generation remains the existing
[oracle workflow](../tools/oracle.py) documented in [README](../README.md#compare-with-vanilla).
On an authorized validation host with Java 25, first run this **separate** action:

```sh
python3 tools/oracle.py inventory --java /absolute/path/to/java25/bin/java \
  --output .cache/vanilla/26.3/identifier-inventory.json
```

The explicit output avoids rewriting the existing tracked identifier inventory.
This action may fetch the official server, verifies its pinned checksum/size,
runs its report generator, and extracts the embedded inner JAR. In Doc's managed
environment, ROOT schedules JVM/native work on the authorized host separately
from active builder jobs. These commands are documentation, not a run receipt.

The resulting cache layout under the checkout is:

```text
.cache/vanilla/26.3/
  server.jar
  minecraft.jar
  generated/reports/
    registries.json
    blocks.json
    commands.json
    datapack.json
    packets.json
    json-rpc-api-schema.json
    minecraft/components/item/*.json
```

The outer JAR SHA-256 is
`d052f14d7a173734fba553711e5b570162e2f2a313267ee31a21b975a679be64`;
the inner JAR SHA-256 is
`a362163eec5d1612d520772bc16e5b39c09e3b234fdc045f56bf544284ee8ae6`.
The map contains each report's byte length/SHA-256 and the sorted item-directory
manifest digest. It also pins the resource manifest. The generator checks the
inner JAR against its member in the outer JAR and the target against
`compatibility/target.json`.

Review-cache files are unnecessary. Optional `review_provenance` records the
design/assessment hashes for reviewers; their paths are never opened. There is
no requirement to obtain private design notes or copy ROOT's evidence cache.
Only the two bounded source annotations are file/hash/anchor checked. Unrelated
README, contract, scenario-map or evidence publication bytes do not determine
surface membership. `features.json` is read for actual, non-deferred family IDs;
its family statuses do not propagate to any surface.

After inputs exist, regeneration and deliberate accounting checks are:

```sh
python3 tools/surface_coverage.py --check
python3 tools/surface_coverage.py --check --complete-inventory
# Author a reviewed new snapshot after deliberately updating pins/assignments:
python3 tools/surface_coverage.py --write
```

To read an already retained cache elsewhere, use
`--artifact-root /absolute/path/to/checkout-with-cache`. That directory is read
only. `--source-root` defaults to this generator's checkout; it supplies the
target, family ledger and bounded source references. `--map` and `--output`
override the authored map and generated index paths.

```sh
python3 tools/surface_coverage.py --catalog > .cache/surface-catalog.json
python3 tools/surface_coverage.py --expand > .cache/surface-rows.jsonl
```

`--catalog` reports fixed source groups and their resolved pins for review;
it never accepts changes into the map. `--expand` emits one row per required
surface/facet with the exact key, source pointer, content hash, source-derived
context and resolved class/open/N/A/unmapped disposition. Its output can be
large and is intentionally not checked in. Read a report pointer against the
corresponding pinned JSON report. Item pointers resolve against the report for
that namespaced item ID; resource pointers name the inner archive member.

Exit codes are 0 for the requested accounting/integrity check, 1 for incomplete
accounting in `--complete-inventory`, and 2 for invalid/missing inputs or a stale
generated index. A successful `--check` proves byte-identical regeneration and
integrity. It does not run a scenario or require all work to be mapped.
`--complete-inventory` additionally rejects unexplained unmapped facets, unknown
source diagnostics, or absent profiles/non-enumerated obligations/limits.
Deliberate open work can pass this mode. `--catalog` cannot be a completion gate.

## Authored groups and review boundary

Surface keys are tagged JSON arrays, never delimiter-concatenated strings.
Fixed source groups cover one registry, all reported block definitions/states,
one command-root subtree (plus the root node), an exact component's defaults,
an exact pack/namespace/nested kind/discriminator, one packet state/direction,
or a named report domain. Selectors accept only an existing exact group or an
explicit member list, optionally with a finite `except` list. There is no
selector language, wildcard fallback, priority or last-match rule.

Each of the 479 assignments pins its reviewed member count, member-set digest
and content digest. Added/removed members, changed values or expanded selectors
are rejected until reviewed and explicitly repinned. Overlapping assignments
for a surface/facet are invalid. Missing dispositions are emitted as `unmapped`.
An exact-source-justified `not_applicable` binds one member, content hash, JSON
pointer and predicate-value hash, plus a concrete rationale. It is counted
separately. Unknown source fields remain diagnostics and original content stays
in the source hashes; changing input pins alone does not clear them.

Canonical JSON uses UTF-8, sorted object keys, compact separators, no ASCII
escaping and no nonfinite numbers. Duplicate JSON keys are rejected. Member
digests hash the canonically sorted array of tagged keys. Content digests hash
sorted `[key, hash(value-and-context)]` pairs. Raw-byte hashes are kept separately.
The compact index stores group pins and dispositions, not repeated state values
or a state-by-facet Cartesian table. It also pins the generator and authored map.

The 22 classes are reusable **obligation templates**. Most explicitly inventory
unassessed work. They assert no implementation equivalence. Two bounded source
reviews distinguish known missing routes: the official clone subtree versus
Rust's positional registration, and cooking recipe-book placement versus the
shared early-return path. Their source hashes and anchors detect stale claims;
they do not prove a runtime outcome. Manual processing cannot cover recipe-book
placement. All other facets remain independently open.

Version 1 deliberately rejects implementation and evidence attachments. Both
`implementation_present` and `paired_covered` therefore remain zero. It neither
imports a top-level `passed` flag nor presents historical observations as current
coverage. A future positive-coverage extension must reuse the existing evidence
validator, binding class membership/facet, parameter partitions, profiles, test
IDs, suite/artifact hashes, reference build and actual engine build. Native-only,
failed, skipped, stale or differently scoped evidence cannot promote a class.
No general importer is introduced here.

## Extraction and acceptance limits

Generated command grammar is separate from session advertisement, permission
evaluation, feature predicates and execution. Permission objects and ancestor
chains remain verbatim; role names are not translated to numeric levels. Nodes
with children can execute. Redirects are graph edges and cycles are not followed.

Default component JSON is an example, never a saved/wire codec schema. Values,
default elision, patch/removal, opaque custom data, direct/reference holder forms,
NBT widths and official network-only persistence classification remain distinct.
Packet IDs establish no framing, field codec, dispatch or gameplay effect.
OpenRPC schemas establish no authentication, enablement or execution.

Descriptors and shipped resources do not prove custom acceptance, tags,
precedence, reload or activation. A shared name does not infer block-to-BE/menu
relations, container privacy, storage roles or entity AI. Only source-provided
relations are emitted: block-to-state, item-to-default component, static-registry
descriptor matches, command ancestry/redirects and resolved OpenRPC references.
Absent relations remain work. Non-enumerated obligations separately preserve
persistence/DFU, framing/security, world/configuration/lifecycle, scheduling and
concurrency/load, coherent survival/multiplayer, custom inputs, independent roles
and family acceptance requirements.

[Six focused tests](../tests/test_surface_coverage.py) cover retained-input
regeneration without private caches, command graph fidelity, exact partitions
and N/A/unmapped accounting, defaults versus schemas, fail-closed evidence
attachments, and independent roles/packs/descriptors. They use synthetic JSON
and ZIPs. They have **not been run in this implementation task**; ROOT owns the
serialized lightweight checks after its current priority run:

```sh
python3 -m unittest discover -s tests -p test_surface_coverage.py -v
```

Actual native and paired-runtime acceptance remains separate from these tests
and from inventory generation. No percentage of Minecraft implementation is
derived by summing these overlapping source domains.
